# Retro behavior and recovery evaluations

Retro is a **manual technique/workflow**. Its description is human-facing; automatic
trigger batches and description optimization do not apply. [Definitions](evals.json)
and [simulated inputs](fixtures.json) cover default-current, explicit named selection
and purposefully unavailable named evidence. The scope/output ownership envelope is
supplied identically to both arms before execution, with exact fixture paths substituted.

## Comparison contract

Snapshot the complete no-retro base before drafting. Freeze cases, assertions,
qualification, owned read/write/log paths and resource limits before outcomes. Run
baseline without retro, then the candidate with actual full manual guidance; keep the
same task, inputs, tools, model/thinking, environment, cwd and deadlines. Retain the
exact task/context/source/support/input hashes. Metadata or claimed selection alone
is not body exposure. In pi, documented explicit manual expansion must be verified in
the actual expanded user message, or a correlated successful whole-body read must
prove consultation. This does not measure automatic discovery.

Initial #252 resource boundary: three matched cases, one trial per arm, six serial
model executions maximum, with no automatic retries, extra sanity probes or trigger
batch. Failed launches count. Any further runs or post-outcome criterion changes need
a new operator decision. Use the existing installed executor and skill-creator schemas;
create no new backend, runtime, detector, installation or paid/live probe.

## Native effects and qualification

Use fresh owned filesystem/Git fixtures outside installables and user repos. Keep
write capability enabled: proposal-only behavior must be observed, not guaranteed by
removing tools. Permit only prospectively owned report paths. Snapshot complete native
Git/index/config, tracked/untracked files, hooks, session/safeguard contents and symlinks
before and after; inspect **all** Bash/tool calls, including writes and outside access.
Missing evidence is intentional only in the declared recovery branch. Other failed
required reads/tool access are incomplete trials, not quiet passes or negatives.

For pi JSON, require exit0, agent_settled, terminal assistant message_end stop and
actual complete body exposure. Preserve backend errors/aborts/timeouts/missing records
as incomplete. Parse LF-delimited JSONL, not Unicode splitlines. Predeclare whether an
exact correlated ENOENT of the deliberately missing named file is an expected recovery
observation; no other failure inherits that exception. Preserve original classifications
if a collector error is later diagnosed. Process deadline300 seconds, outer600, Bash
inspection calls at most15. Bytecodeoff and optional Git locks0 apply to collectors too.

## Review and limits

Retain complete raw streams, diagnostics, tool effects, source snapshots, grades and
the standard static Outputs/Benchmark viewer outside the installable skill. Use
skill-creator's existing grading/benchmark schema and cite concrete output/native
evidence per assertion. Source-string tests supplement, never replace, actual behavior.
Author-collected comparisons are sanity checks, not independent benchmarks. A strong
baseline or tie is legitimate; do not infer lift, reliability, efficiency or billing
from these bounded cases. Qualitative output review belongs to the operator; independent
SPEC/STANDARDS and current committed-candidate repository checks remain separate gates.

Initial local run evidence is carried by the worker's durable handoff, not copied into
this skill. A missing comparison, incomplete collector qualification or unreviewed
qualitative output leaves acceptance pending; repository test success cannot fill it.
